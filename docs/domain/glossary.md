# Harness Domain Glossary

This glossary contains the ubiquitous language of the harness domain.

Terms are exploratory until explicitly stabilized.

## Idea

A candidate opportunity or change worth investigating.

## Requirement

A statement describing behavior, capability, quality, or constraint
that a system is expected to satisfy.

## Decision

The recorded resolution of a meaningful question.

## Architecture Baseline

An accepted, versioned representation of system structure for a
particular scope.

## Question

Explicit unresolved uncertainty.

## Evidence

Information supporting or disproving a claim.

## Invariant

A condition that must remain true for a domain object or transition
to be valid.

## Transition

A valid change from one domain state to another.
